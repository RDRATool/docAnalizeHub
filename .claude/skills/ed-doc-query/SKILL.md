# ED書 照会

`replaceMd/02_ED書` を、`replaceMd/viewer-ed/ed-graph-data.js`（753ノード / 2097関係）の
参照関係グラフ経由で引く。**全文grepより先にこのグラフを引く。** 探索範囲が数百ファイルから
数件に絞れ、根拠となった原文行と確度（確実／推定）も一緒に取れる。

## 使い方

リポジトリルート（`replaceMd` がある階層）から実行する。Node のみ、依存なし。

```bash
node .claude/skills/ed-doc-query/scripts/ed-query.mjs <command> [key] [options]
```

**3ステップで答える。**

1. `find <語>` で対象ノードを特定する（IDでも名称の一部でもよい）
2. `refs` / `trace` / `path` で参照関係と根拠を取る
3. `files` / `show` が返した `.md` を Read して本文で裏を取る

| command | 用途 |
| --- | --- |
| `find <語> [--kind screen\|batch\|file\|flow\|table\|screengroup\|batchgroup]` | 種別横断で探す |
| `show <key> [--refs]` | 詳細（概要・利用テーブル・入出力一覧・実体 .md パス） |
| `refs <key> [--dir out\|in] [--type crud] [--certain]` | 発／被の参照を関係種別ごとに根拠付きで |
| `trace <key> [--depth N] [--dir out\|in]` | 多段の波及（影響調査） |
| `path <A> <B>` | 2つの仕様書がどう繋がっているか |
| `files <key>` | Read すべき .md のパスだけ |
| `matrix` | 種別×関係×参照元項目×参照先 の全体集計（TSV） |
| `issues [--kind orphan\|missing\|unresolved\|skip]` | 未解決参照・孤立・詳細なしフロー |

共通オプション: `--json`（機械処理向け）、`--limit N`（既定12）、`--root <repo>`。
`key` は ノードID / `SE001_F03` `BT016_B01` `GF_030` `KO006` のようなID / 名称の部分一致。
候補が複数あれば一覧を出して終了するので、絞って再実行する。

このワークスペースの既定シェルは PowerShell 5 で `&&` が使えない。連結は `;` を使う。

## ドキュメント種別ごとの参照関係（早見表）

参照は **詳細業務フロー → 画面／バッチ → ファイル／TBL** の一方向に流れる。
ファイル仕様からの発参照はゼロ、業務フローへの被参照もゼロ。

| 参照元 | 参照元の項目 | 参照先 | 件数 | 確度 |
| --- | --- | --- | --- | --- |
| 20_画面仕様 | `01_機能概要` の【利用テーブル】（C/R/U/D） | TBL | 378 | 確実（表） |
| 20_画面仕様 | `ED_T_画面遷移図/01_画面遷移一覧` の遷移契機 | 20_画面仕様 | 53 | 確実（表） |
| 20_画面仕様 | ファイルID前方一致・ファイル仕様の機能名一致 | 60_ファイル仕様 | 37 | 確実 |
| 30_バッチ処理仕様 | `概要` の ◆入力一覧（区分 TBL/DB） | TBL | 338 | 確実（表） |
| 30_バッチ処理仕様 | `概要` の ◆出力一覧（区分 TBL/DB） | TBL | 255 | 確実（表） |
| 30_バッチ処理仕様 | ◆入力一覧／◆出力一覧（区分 CSV等） | 60_ファイル仕様 | 92 | 確実（表） |
| 30_バッチ処理仕様 | ◆入力一覧／◆出力一覧（区分 引数・環境変数等） | データ（派生） | 40 | 確実（表） |
| 110_詳細業務フロー | 本文の `〜TBL` | TBL | 295 | 抽出（本文） |
| 110_詳細業務フロー | 本文の画面ID・画面名／機能ID | 20_画面仕様 | 95 | ID 32 / 名称 63 |
| 110_詳細業務フロー | 本文のバッチID・バッチ名／機能ID | 30_バッチ処理仕様 | 71 | ID 21 / 名称 50 |
| 110_詳細業務フロー | 本文のファイル名一致 | 60_ファイル仕様 | 39 | 全件が推定 |
| 110_詳細業務フロー | 本文の担当表記・`TPC_D05` 等 | アクター／起動契機（派生） | 130 | 辞書・正規表現 |

**確実と推定を混ぜて答えない。** `refs` の各行末に `確実(表)` `確実(ID一致)` `推定(名称一致)`
`抽出(本文)` が付く。推定は名前が似ているだけなので、必ず原文で裏を取ってから断定する。

## 実体ファイルの構造

`show` / `files` が返すパスは `replaceMd/02_ED書/` 配下の実在する `.md`。
`.xlsx` はフォルダ名で、その中の `NN_シート名.md` が1シート。

| 種別 | よく読むシート |
| --- | --- |
| 20_画面仕様 | `01_機能概要`（概要・利用テーブル）、`02_画面項目`、`03_画面状態`、`04_イベント仕様`、`05_チェック仕様` |
| 30_バッチ処理仕様 | `概要`（◆入力一覧・◆出力一覧・処理概要）、`処理フロー`、`N. 処理名`、`補足` |
| 60_ファイル仕様 | `01_ファイル仕様`（物理名・形式）、`02_データリスト`（項目定義） |
| 110_詳細業務フロー | `NN_GF_xxx_フロー名.md` 1シート1フロー |

## グラフに載っていない種別

`10_機能仕様` `40_帳票仕様` `50_データベース仕様` `70_コード仕様` はグラフ化されていない。
Glob と Grep で直接引く。

- TBL の定義書: `show <TBL名> --kind table` が `50_データベース仕様` の候補を**名寄せで**出す。
  完全一致以外（`分割TBL` `部分一致`）は当てずっぽうなので、開いて物理名で確認する。
- 帳票・コード: `replaceMd/02_ED書/40_帳票仕様/*.md`、`70_コード仕様/**` を Grep。

## 回答の作り方

- 件数・ID・シート名を添える。「SE001_F03 が請求書管理TBL を CRUD（`01_機能概要` の利用テーブル）」のように、
  **どのドキュメントのどの項目に書いてあるか**まで書く。
- 推定リンクに依存した結論には「名称一致による推定」と明示する。
- 影響調査では `trace --depth 2` の結果をそのまま貼らず、種別ごとに集約して件数と代表例を示す。
- 読んだ `.md` のパスを回答に残す。

## 注意点

- `110_詳細業務フロー` は元が Excel の図形なので、**詳細シートがある38フローの本文は
  すべてAIが画像から再構成したテキスト**。`show` に「原本要確認」と出る。重要な判断の前に元の図を見る。
- 69フローのうち詳細シートがあるのは38件で、残り31件は一覧の行だけ（`issues --kind missing`）。
  この31件の関係はすべて名称一致の推定。
- TBLノード170件は各仕様書からの抽出で作った**派生ノード**で `50_データベース仕様` と未突合。
  `請求/収納進捗TBL` と `請求収納進捗TBL` のような表記ゆれが別ノードのまま残っている。
- バッチの入出力一覧の備考には「詳細はファイル仕様書「ED_T_〜.xlsx」参照」という明示的な参照が
  27件あるが、グラフのエッジにはなっていない。`show <バッチ>` が「備考の文書参照」として出すので、
  ファイル特定はそちらを優先する。
- Excel のふりがながセル本文の末尾に連結されている（`掲示板ケイジバン`、`〜参照ショウサイシヨウショサンショウ`）。
  `.md` を直接読むときも同じなので、末尾のカタカナは読み仮名として無視する。
  ただし「モバイル回線別レポート」のように語そのものがカタカナで終わる名前もあるので、切り捨てて解釈しない。
- グラフは生成物。元データを更新したら `replaceMd/viewer-ed/README.md` の手順で再生成する。

より詳しい関係の一覧・データ構造・ID体系は [reference.md](reference.md) を読む。
