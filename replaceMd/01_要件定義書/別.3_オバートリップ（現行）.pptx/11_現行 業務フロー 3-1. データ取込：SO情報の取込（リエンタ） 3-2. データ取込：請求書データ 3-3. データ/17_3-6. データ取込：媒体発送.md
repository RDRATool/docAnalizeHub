# 別.3.1 現行 業務フロー（オバートリップ）
## 概要
3-6. データ取込：媒体発送において、キャリアが媒体を発送し、運用担当が受取および到着管理を行う。統合回線システムを用いて待受情報の抽出と到着登録を行い、未着不一致が発生した場合はCS担当が調査・回答受領までを行い、最終的に媒体を読込してロード処理へ進む流れを示す。

## 業務フロー
1.媒体発送(キャリア) - CD/FD郵送, メール連絡 -> 2.媒体受取(運用担当)
2.媒体受取(運用担当) -> 3.媒体到着管理(運用担当)
3.媒体到着管理(運用担当) は 統合回線システム(他システム) から待受情報を抽出する
3.媒体到着管理(運用担当) は 統合回線システム(他システム) に媒体到着情報を登録する
3.媒体到着管理(運用担当) -> 3.1.未着不一致 連絡(SO統括/CS担当)
3.1.未着不一致 連絡(SO統括/CS担当) -> 3.2.未着不一致 調査(SO統括/CS担当)
3.2.未着不一致 調査(SO統括/CS担当) は 顧客 へ調査依頼する場合がある
3.2.未着不一致 調査(SO統括/CS担当) -> 3.3.未着不一致 回答受領(SO統括/CS担当)
3.3.未着不一致 回答受領(SO統括/CS担当) -> 3.媒体到着管理(運用担当)
3.媒体到着管理(運用担当) -> 4.媒体読込(運用担当)
4.媒体読込(運用担当) は 媒体管理 DB(オバートリップ) を参照し、各キャリアの明細情報を媒体処理SVへ読込、オバートリップ用にフォーマット変換を（手動でShellにて）実施する
4.媒体読込(運用担当) - 突合用.CSV -> 4-1.ロード処理：請求書、Web明細、媒体発送へ(運用担当)
