# 別.3.1 現行 業務フロー（オバートリップ）
## 7-1. 請求：銀行振込（電子請求）
## 概要
顧客がメールで請求通知を受信し、承認・ダウンロードを経て支払処理を行う流れと、並行して運用担当者が請求データの取得から管理簿チェック、売上計上データの保存を行い、統合債権システム（N-Active）経由でみずほ銀行にて収納処理を行う一連の流れを示す。

## 業務フロー
1.メール受信(顧客) -> 2.1.お客様承認(顧客)
2.1.お客様承認(顧客) -> 2.2.自動承認 通知受領(顧客)
2.2.自動承認 通知受領(顧客) -> 4.電子請求 ダウンロード(顧客)
4.電子請求 ダウンロード(顧客) -> 5.支払処理(顧客)
2.2.自動承認 通知受領(顧客) -> 3.1.請求データ 取得(運用担当) // 承認処理が行われたタイミングで請求書（PDF）が作成される
3.1.請求データ 取得(運用担当) -> 3.2.経理ツール へデータ取込(運用担当)
3.2.経理ツール へデータ取込(運用担当) -> 3.3.請求管理簿 出力(運用担当)
3.3.請求管理簿 出力(運用担当) -> 3.4.請求管理簿 チェック(運用担当) // 請求管理簿と統合債権用請求.TSV、請求書（PC請求書）.csv、口座データ.TXTの整合性をチェック
3.4.請求管理簿 チェック(運用担当) -> 3.5.売上計上用 データ出力(運用担当)
3.5.売上計上用 データ出力(運用担当) -> 3.6.請求/売上 計上用データ保存(運用担当)
3.6.請求/売上 計上用データ保存(運用担当) -> 統合債権システム(他システム) // 統合債権用請求データ（TSV）と売上計上データをファイルサーバ経由で送信
統合債権システム(他システム) -> 6.収納(みずほ銀行 他システム)
6.収納(みずほ銀行 他システム) -> 7-3.収納 銀行振込へ(みずほ銀行 他システム)
