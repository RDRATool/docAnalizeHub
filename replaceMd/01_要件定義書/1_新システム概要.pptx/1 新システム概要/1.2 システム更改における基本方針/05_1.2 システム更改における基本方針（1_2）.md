# 1_新システム概要 - スライド5

- 1.2 システム更改における基本方針（1/2）

## 表

| 項番 | システム化方針 |
| --- | --- |
| 1 | オバートリップについては、既存機能をベースに不要な機能は削除し、作り直しとする。さらに業務、機能の改善を図る。 |
| 2 | ABC北日本・ABC南日本からの要望による、PRIME/CUSTOMの請求データのWeb提供機能等を具備する。 |
| 3 | 機能間の依存度を低くし、次の改修時に他の機能に影響を与えないようにする（マイクロサービス化、モジュール化）。また、機能間はAPIによる連携とする。 |
| 4 | システムに必要な機能を極力、他社サービスや、OSS、市販ツール、パッケージ等で置き換え、スクラッチ開発の割合を低減する。 |
| 5 | 他システムとはAPI連携を可能とする。 |
| 6 | ABCファイナンス社へのOEM提供を例として、今後テナントを増やせる構造にする（マルチテナント機能）。 |
| 7 | 現行オバートリップで利用している認証基盤の「セキュアコネクト」サービスについては、独自の認証方式に置き換える。 |
| 8 | 基盤については、クラウド基盤を採用する。 |
