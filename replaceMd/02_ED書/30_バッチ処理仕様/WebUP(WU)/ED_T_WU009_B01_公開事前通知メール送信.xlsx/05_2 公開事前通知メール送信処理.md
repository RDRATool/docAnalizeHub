# 2. 公開事前通知メール送信処理

## 概要
1.で抽出したカスタマを公開メール送信対象とし、公開メールを送信する。

## 2-1. 公開事前メール送信
- メール送信機能は、共通機能を使用する。
- ※API呼出要領は「2-3. メールAPI呼出」を参照。

## 2-2. メールAPI呼出

### 2-2-1. メール本文取得処理
以下の設定内容でメール本文取得API（REST-API）の呼出を行う。

**(1) 1.で抽出した合算区分='1'(合算)の場合**

| 項目 | 設定内容 | 備考 |
| :--- | :--- | :--- |
| API名 | メール本文取得API | |
| 設定：DB接続情報 | （設定ファイルより取得）メールAPI-DB接続情報 | |
| 設定：ユーザＩＤ | 機能ＩＤ | |
| 設定：顧客ＩＤ | 1.で抽出したカスタマID | |
| 設定：テナント会社コード | 入力パラメータ.サービス提供会社コード | |
| 設定：件名パターンNo. | 固定値'01' | |
| 設定：ヘッダーパターンNo. | 固定値'01' | |
| 設定：本文パターンNo. | 固定値'01' | |
| 設定：フッターパターンNo. | 固定値'01' | |
| 戻り値：ステータスコード | 1:正常、2:失敗、3:DB異常 | |
| 戻り値：パターン本文 | [{"OUT_Text"},{"OUT_Text":""},{"OUT_Text":""},{"OUT_Text":""}] | 左から順に、件名、ヘッダ、本文、フッタ |

**(2) エラー処理**
戻り値のステータスコードが'1'（正常）以外の場合、エラーログ出力し、処理終了する。

### 2-2-2. メール本文作成処理
取得したメールの件名、ヘッダ、本文に埋込文字を設定する。

**(1) 1.で抽出した合算区分='1'(合算)の場合**

- **(1)-1. 件名作成**
    - 内容：`[オバートリップ] 請求情報確定準備中のご利用について`
    - ※件名は埋込文字なし

- **(1)-2. ヘッダ作成**
    - 処理：2-2-1.で取得したパターン本文の2列目のメッセージと、以下の埋込文字列を引数に設定し、「共通処理.メール送信設定取得」を呼出する。
    - 埋込文字列：`0：1.で取得した顧客名`
    - 結果：
      `{0}様`
      `いつも弊社統合請求サービス『オバートリップ』をご利用いただき`
      `誠にありがとうございます。`

- **(1)-3. 本文作成**
    - 処理：2-2-1.で取得したパターン本文の3列目のメッセージと、以下の埋込文字列を引数に設定し、「共通処理.メール送信設定取得」を呼出する。
    - 埋込文字列：
        - `0：1.で抽出した請求年月（YYYY）`
        - `1：1.で抽出した請求年月（MM）`
        - `2：1.で抽出した承認期限日（YYYY）`
    - 結果：
      `請求情報確定準備中のため、{0}年{1}月{2}日は`
      `管理情報設定のご利用は参照のみとなります。`
      `お客様には大変ご迷惑をおかけいたしますが、ご理解賜りますよう`
      `宜しくお願いいたします。`

- **(1)-4. フッタ作成**
    - 内容：`今後ともご愛顧いただきますようお願い申し上げます。`
    - ※フッタは埋込文字なし

### 2-2-3. 送信先メールアドレス取得処理
宛先のメールアドレスを各テーブルから抽出する。

| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | ユーザー管理TBL |
| 抽出項目 | ユーザー管理TBL．連絡先Ｅメールアドレス |
| 抽出条件 | ユーザー管理TBL．サービス提供会社コード ＝ 外部パラメータ．サービス提供会社コード<br>かつ<br>ユーザー管理TBL．カスタマＩＤ ＝ 1.で取得したカスタマID<br>かつ<br>ユーザー管理TBL．有効開始年月 ≦ 1.で取得した請求年月 |

#### 修正・削除履歴（メモ）
- 表示日付の設定値変更に伴い、取得不要となったため、処理を削除
- システム日付に変更
- 表示日付の設定値変更に伴い、注記不要となったため、削除
