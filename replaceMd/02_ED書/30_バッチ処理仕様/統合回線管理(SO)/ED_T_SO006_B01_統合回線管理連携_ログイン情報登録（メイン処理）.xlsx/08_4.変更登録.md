# 4. 変更登録

初回月/当月/次月以降に対する変更か、有効開始/終了に変更があるか、組み合わせによって処理を変更する。

### 想定パターン
- **月に対する変更**
    - 初回月に対する変更
    - 当月に対する変更
    - 次月以降に対する変更
- **期間に対する変更**
    - 有効開始年月を前の月へずらす
    - 有効開始年月を後の月へずらす

## 4-1. 変更対象データの存在チェック（期間に空があるかどうか）

### ユーザー管理TBL チェック
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | ユーザー管理TBL |
| 抽出 | 件数 |
| 条件 | ログインID = ログインリエンタ情報ファイル．ログインID<br>有効開始年月 $\le$ ログインリエンタ情報ファイル名．請求年月<br>有効終了年月 $\ge$ ログインリエンタ情報ファイル名．請求年月<br>サービス提供会社コード ＝ 引数.サービス提供会社コード |
| 備考 | 検索結果が0件の場合、エラー。 |

### セキュリティTBL チェック
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | セキュリティTBL |
| 抽出 | 件数 |
| 条件 | ログインID = ログインリエンタ情報ファイル．ログインID<br>有効開始年月 $\le$ ログインリエンタ情報ファイル名．請求年月<br>有効終了年月 $\ge$ ログインリエンタ情報ファイル名．請求年月<br>サービス提供会社コード ＝ 引数.サービス提供会社コード |
| 備考 | 検索結果が0件の場合、エラー。 |

### エラー処理
エラーが発生した場合は、回線管理連携エラー情報TBLに挿入/更新する。（「回線管理連携エラー情報登録-登録パターンD」シートを参照）
- **エラー内容**: TPC_T_E_0012
- **備考**: 存在しない場合、期間に空がありデータを更新できない旨のメッセージを設定する。

## 4-2. 変更月の判定（初回月なのか、当月なのか、次月以降なのか）

次月以降に対する変更の場合、履歴管理するために新レコードを作成する必要があるため変更月の判定を行う。

### 共通処理の呼び出し
以下の共通処理を呼び出し、変更年月の判定を行う。
- **処理名**: 請求年月の判定処理
- **引数**: 
    - カスタマID
    - ログインリエンタ情報ファイル名．請求年月
    - サービス提供会社コード
- **戻り値**: 判定結果（過去月・初回月以前・当月・次月以降・判定エラー・取得エラー）
- **設定先**: 変更月
- **参照**: 「T_SO000_B01_統合回線管理連携（共通処理）」の「1.請求年月の判定処理」を参照

## 4-3. 有効開始年月/有効終了期間に変更があるか判定する

期間に変更がある場合は、TBLへの影響範囲が異なるため判定する。

| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | ユーザー管理TBL |
| 条件1 | ユーザー管理TBL.ログインID ＝ ログインリエンタ情報ファイル.ログインID |
| 条件2 | ユーザー管理TBL.有効開始年月の最小 $\neq$ （判定値） |
