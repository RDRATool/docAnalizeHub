# 統合回線管理連携_ログイン情報登録（メイン処理）

## 処理概要
ログインリエンタ情報ファイルがアップロードされた場合、登録区分によってユーザー管理TBLとセキュリティTBLを作成/更新する。
※[エラー]のレコードはコミットしない。[お知らせ]のレコードはコミットする。

- **対象ファイル**：ログインリエンタ情報ファイル
- **引数**：依頼受付番号

## メイン処理フロー
Start -> 1. 登録ファイル チェック -> 2. 登録区分の判定 -> (3. 新規登録 / 4. 変更登録 / 5. 廃止登録) -> 6. 各登録処理後の処理 -> End

---

## 1. 登録ファイル チェック
### 概要
[1.登録ファイルチェック]の詳細。ファイル内のレコード数分実行する。

### 処理フロー
Start -> 1-1. ファイルの取得 -> 1-2. ファイル名チェック -> 1-3. ファイルフォーマットチェック -> 1-4. 単項目チェック -> 1-5. 項目間の相関チェック -> 1-6. 関連TBLとの相関チェック -> 1-7. エラーファイル出力 -> End

#### 1-2. ファイル名チェック 詳細
Start -> 1-1-(1). 請求年月取得 -> 1-1-(2). 請求年月の存在チェック -> End

#### 1-5. 相関チェック 詳細
Start -> 1-5-(1). 期別チェック -> 1-5-(2). 開始期別チェック -> 1-5-(3). 廃止期別チェック -> 1-5-(4). 連絡先メールアドレスチェック -> End

---

## 2. 登録区分の判定
### 処理フロー
Start -> (1)-(ア)回線管理連携エラー情報TBLに登録 / (1)-(イ)-(a)ユーザー管理タンキングTBLへ挿入 / (1)-(イ)-(b)セキュリティ管理タンキングTBLへ挿入 / (2)-(ア)ユーザ管理TBLの更新 / (2)-(イ)セキュリティTBLの更新 -> End

---

## 4. 変更登録
### 概要
[4.変更登録]の詳細。

### 処理フロー
Start -> 4-1. 変更対象データの存在チェック -> 4-2. 変更月のチェック -> 4-3. 有効期間のチェック -> 4-4. 処理分岐 -> (4-5. 有効開始年月の変更 / 4-6. 期間以外の変更) -> End

#### 4-5. 有効開始年月の変更 詳細
Start -> 4-5-(1). ユーザ管理TBLの更新 -> 4-5-(2). セキュリティTBLの更新 -> End

#### 4-6. 期間以外の変更 詳細
Start -> 4-6-(1). 更新対象データの取得 -> 4-6-(2). レコードチェック -> 4-6-(3). 更新対象データの取得 -> 4-6-(4). レコードチェック -> 4-6-(5). ファイルの変更情報に変更 -> End

---

## 5. 廃止登録
### 処理フロー
Start -> 5-1. 未来レコードの存在チェック -> 5-2. データの取得 -> 5-3. ファイル情報の変更 -> End

---

## 6. 各登録処理後の処理
### 処理フロー
Start -> 6-1. 依頼TBLの更新 -> 6-2. 処理結果返却 -> End
