# 3. 疑似登録処理(請求書情報)

請求マスタTMPTBLを作成し、仮想口座管理TBLを更新する。

## 3-1. ファイル処理単位で正常終了しないレコードNOを取得する
後続の口座情報抽出処理で使用するため、請求情報登録処理でエラー/お知らせ(重複登録のみ)メッセージを登録したレコードNOを取得しておく。

## 3-2. 登録区分の判定
登録区分を判定し、以下の処理を行う。

### (1) [1：新規]の場合
#### (ア) 請求マスタTMPTBLにデータが存在するか確認する
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | 請求マスタTMPTBL |
| 条件 | 依頼受付番号 ＝ 引数.依頼受付番号 かつ<br>カスタマID ＝ 請求リエンタ情報ファイル.カスタマID かつ<br>請求番号 ＝ 請求リエンタ情報ファイル.請求番号 かつ<br>サービス提供会社コード ＝ 引数.サービス提供会社コード |

- エラーが発生した場合は、回線管理連携エラー情報TBLに挿入/更新する（「回線管理連携エラー情報登録-登録パターンD」シートを参照）。
    - エラー内容：`TPC_T_I_0001`
- 存在する場合、すでにデータが登録されているためエラーメッセージを登録する。

#### (イ) 仮想口座管理TBLにデータが存在するか確認する
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | 仮想口座管理TBL |
| 抽出条件 | カスタマID ＝ 請求リエンタ情報ファイル.カスタマID かつ<br>請求番号 ＝ 請求リエンタ情報ファイル.請求番号 かつ<br>削除区分 ＝ "0"(生) |

- 存在する場合、以降の処理で仮想口座管理TBL登録を行わない。

#### (ウ) [3-3]の処理を行う。

---

### (2) [2：変更]の場合
#### (ア) 請求マスタTMPTBLに変更対象レコードが存在するか確認する
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | 請求マスタTMPTBL |
| 条件 | 依頼受付番号 ＝ 引数.依頼受付番号 かつ<br>カスタマID ＝ 請求リエンタ情報ファイル.カスタマID かつ<br>請求番号 ＝ 請求リエンタ情報ファイル.請求番号 かつ<br>削除区分 ＝ "0"(生) かつ<br>サービス提供会社コード ＝ 引数.サービス提供会社コード |

- 存在しない場合、エラーメッセージを設定する。
- エラーが発生した場合は、回線管理連携エラー情報TBLに挿入/更新する（「回線管理連携エラー情報登録-登録パターンD」シートを参照）。
    - エラー内容：`TPC_T_E_0020`

#### (イ) [3-4]の処理を行う。

---

### (3) [3：廃止]の場合
#### (ア) 請求マスタTMPTBLに廃止対象レコードが存在するか確認する
| 項目 | 内容 |
| :--- | :--- |
| テーブル名 | 請求マスタTMPTBL |
| 条件 | 依頼受付番号 ＝ 引数.依頼受付番号 かつ<br>カスタマID ＝ 請求リエンタ情報ファイル.カスタマID かつ<br>請求番号 ＝ 請求リエンタ情報ファイル.請求番号 かつ<br>削除区分 ＝ "0"(生) かつ<br>サービス提供会社コード ＝ 引数.サービス提供会社コード |

- 存在しない場合、エラーメッセージを設定する。
- エラーが発生した場合は、回線管理連携エラー情報TBLに挿入/更新する（「回線管理連携エラー情報登録-登録パターンD」シート参照）。

## 変更処理フロー（回線管理より 200409変更分）
- (ア) 変更する有効終了年月より有効開始年月が未来のレコードが存在するか
    - YES $\rightarrow$ 処理中の請求情報ファイルレコードに対する処理を続行したまま、エラーメッセージの登録を行う。
    - NO $\rightarrow$ (イ) 更新対象レコードが存在するか
        - NO $\rightarrow$ (エ) 新しいレコードを作成する
        - YES $\rightarrow$ (ウ) そのまま変更OKか、新しいレコードが必要か判定する
            - YES $\rightarrow$ 削除対象レコードの削除
            - NO $\rightarrow$ 履歴コード作成 $\rightarrow$ (オ) 有効終了年月を含み、請求情報ファイルの変更情報に変更する
