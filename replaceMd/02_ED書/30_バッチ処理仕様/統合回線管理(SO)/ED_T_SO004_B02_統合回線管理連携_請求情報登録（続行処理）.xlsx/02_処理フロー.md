# 統合回線管理連携_請求情報登録（続行処理）

## 概要
請求情報の登録における続行処理を行う。
- 対象ファイル：請求リエンタ情報ファイル
- 引数：依頼受付番号

## 処理フロー
Start -> 1. 処理対象区分の取得 -> 2. 続行処理 -> 3. DB更新 -> End

※処理対象区分：
- 処理続行
- 対象外
- 処理中止

---

# [1.処理対象区分の取得]の詳細

## 処理フロー
Start -> 1-1. 処理対象区分の取得

- ※「対象外」が含まれていた場合
  1-1. 処理対象区分の取得 -> 1-2-(1). [3.DB更新] >[(1)]へ -> End
- ※「処理続行」の場合
  1-1. 処理対象区分の取得 -> 1-2-(2). [2.本登録]へ -> End
- ※「処理中止」の場合
  1-1. 処理対象区分の取得 -> 1-2-(3). [3.DB更新] >[(3)]へ -> End

---

# [2.続行処理]の詳細

## 処理フロー
Start -> 2-1-(1). ファイルから カスタマIDを抽出 -> 2-1-(2). 請求マスタDB データ削除 -> 2-1-(3). 請求マスタDB データ登録 -> 2-2-(1). 回線管理連携請求情報TEMPDB から項目抽出 -> 2-2-(2). 仮想口座管理DB 登録 -> 2-3-(1). ファイルから カスタマIDを抽出 -> 2-3-(2). 振替元マスタDB データ削除 -> 2-3-(3). 振替元マスタDB データ登録 -> End

---

# [3.DB更新]の詳細

## 処理フロー
Start -> (条件分岐)

- ※「対象外」が含まれていた場合
  Start -> 3-1-(1). 依頼DBの更新 「異常終了」 -> 3-1-(2)-(ア). 回線管理連携 エラー情報DB のレコード削除 -> 3-1-(2)-(イ). 依頼DBの更新 「正常終了」 -> 3-2. エラーファイル出力 -> 3-3. 処理結果返却 -> End
- ※「処理続行」の場合
  Start -> 3-1-(3)-(ア). 回線管理連携 エラー情報DB の更新 -> End
- ※「処理中止」の場合
  Start -> 3-1-(3)-(イ). 依頼DBの更新 「異常終了」 -> End
