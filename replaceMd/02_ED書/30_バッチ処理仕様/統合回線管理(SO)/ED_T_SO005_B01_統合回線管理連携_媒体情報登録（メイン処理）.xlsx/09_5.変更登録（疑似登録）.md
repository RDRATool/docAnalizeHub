# 5. 変更登録（疑似登録）

## 概要
DBのコネクトエラーやサーバークラッシュ以外のエラーは、エラーメッセージを回線管理連携エラー情報TBLに設定し、次のレコードの処理に移る。
初回月/当月/次月に対する変更か、有効開始/終了に変更があるかの組み合わせによって処理を変更する。

### 想定パターン
- **月に対する変更**
    - 初回月に対する変更
    - 当月に対する変更
    - 次月以降に対する変更
- **期間に対する変更**
    - 有効開始年月を前の月へずらす
    - 有効開始年月を後の月へずらす
    - 有効終了年月を前の月へずらす
    - 有効終了年月を後の月へずらす

---

## 5-1. 変更月の判定
次月以降に対する変更の場合、履歴管理するために新レコードを作成する必要があるため変更月の判定を行う。

### 共通処理：請求年月の判定処理
以下の共通処理を呼び出し、変更年月の判定を行う。
※「T_SO000_B01_統合回線管理連携（共通処理）」の「1.請求年月の判定処理」を参照。

| 項目 | 内容 |
| :--- | :--- |
| 処理名 | 請求年月の判定処理 |
| 引数 | カスタマID、媒体リエンタ情報ファイル名、請求年月、サービス提供会社コード |
| 戻り値 | 判定結果（過去月・初回月以前・当月・次月以降・判定エラー・取得エラー）、変更月 |

### 判定イメージ（当月：2004/07の場合）
| 有効開始年月 | 有効終了年月 | 判定 |
| :--- | :--- | :--- |
| 200404 | 999912 | 当月 |
| 200404 | 200408 | 当月 |
| 200409 | 999912 | 次月以降 |

---

## 5-2. 判定結果に基づくエラー判定
(1)の判定結果を基にエラー判定を行う。

### エラー判定マトリクス
| (1)の判定結果 | 結果 | 備考 |
| :--- | :--- | :--- |
| 当月 | エラー | ※1 |
| 判定エラー | エラー | ※2 |
| 過去月 | エラー | ※3 |
| 取得エラー | エラー | ※4 |

### エラー詳細
エラーが発生した場合は、回線管理連携エラー情報TBLに挿入/更新する（「回線管理連携エラー情報登録-登録パターンD」シートを参照）。

- **※1：サービス公開済みエラー**
    - 内容：サービスが公開されているため、変更できずエラー。
    - エラー内容：`TPC_T_E_0017`
- **※2：変更月判定エラー**
    - 内容：変更月の判定エラー。
    - エラー内容：`TPC_T_E_0001`
- **※3：過去月変更エラー**
    - 内容：過去月は変更ができずエラー。
    - エラー内容：`TPC_T_E_0022`
- **※4：取得エラー**
    - 内容：取得エラー。以下の内容をログに出力する。
    - エラー内容：`TPC_L_E_0022`

---

## 5-3. 開始期間に変更があるかの判定
開始期別に変更がある場合、変更前の媒体期別群で廃止にし、変更後の媒体期別群で新規を受ける運用となる。そのため、登録区分「変更」で開始期別に変更がある場合はエラーとする。

### 判定処理
- **テーブル名**: 媒体管理TMPTBL
- **抽出項目**: 請求年月の最小値
- **条件**: カスタマID

---

## 補足：処理フローおよびデータイメージ

### 判定フロー
- 媒体読込が行われているか (1)
    - YES $\rightarrow$ 処理継続
    - NO $\rightarrow$ (2)へ

### データ遷移イメージ
回線管理からの変更登録におけるレコードの変化例。

- **1回目（新規登録時）**
    - 状態：`新規 PRIME 電話 番明 * 200407 C AAAAA 200407A`
    - 登録後：`PRIME 電話 番明 00 * 200407 C AAAAA 200407A` / `PRIME 電話 番明 01 * 200407 C AAAAA 200407A`
- **2回目（変更登録時）**
    - 状態：`変更 PRIME 電話 番明 9999 200407 C AAAAA 200407A`
    - 登録後：`PRIME 電話 番明 00 9999 200407 C AAAAA 200407A` / `PRIME 電話 番明 01 * 200407 C AAAAA 200407A`
