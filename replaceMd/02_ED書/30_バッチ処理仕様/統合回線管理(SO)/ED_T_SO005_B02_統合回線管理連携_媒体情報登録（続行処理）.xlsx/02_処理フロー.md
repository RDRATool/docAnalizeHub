# 統合回線管理連携_媒体情報登録（続行処理）

## 概要
媒体情報の登録における続行処理を行う。

- **対象ファイル**：媒体リエンタ情報ファイル
- **引数**：依頼受付番号

## 処理フロー
Start -> 1. 処理対象区分の取得 -> 2. 続行処理 -> 3. DB更新 -> End

---

## [1.処理対象区分の取得]の詳細
## 処理フロー
Start -> 1-1. 処理対象区分の取得

- 1-1. 処理対象区分の取得 ‐ ※「対象外」が含まれていた場合 ‐> 1-2-(1). [3.DB更新] >[(1)]へ -> End
- 1-1. 処理対象区分の取得 ‐ ※「処理続行」の場合 ‐> 1-2-(2). [2.本登録]へ -> End
- 1-1. 処理対象区分の取得 ‐ ※「処理中止」の場合 ‐> 1-2-(3). [3.DB更新] >[(3)]へ -> End

---

## [2.続行処理]の詳細
## 処理フロー
Start -> 2-1-(1). TMPDBから カスタマIDを抽出 -> 2-1-(2). 媒体管理DB データ削除 -> 2-1-(3). 媒体管理DB データ登録 -> 2-2. 進捗管理DB 削除 -> End

---

## [3.DB更新]の詳細
## 処理フロー
- **※「対象外」が含まれていた場合**
  Start -> 3-1-(1). 依頼DBの更新 「異常終了」 -> 3-2. エラーファイル出力 -> 3-3. 処理結果返却 -> End

- **※「処理続行」の場合**
  Start -> 3-1-(2)-(ア). 回線管理連携 エラー情報DB の更新 -> 3-1-(2)-(イ). 依頼DBの更新 「正常終了」 -> 3-3. 処理結果返却 -> End

- **※「処理中止」の場合**
  Start -> 3-1-(3)-(ア). 回線管理連携 エラー情報DB の更新 -> 3-1-(3)-(イ). 依頼DBの更新 「異常終了」 -> 3-2. エラーファイル出力 -> 3-3. 処理結果返却 -> End
