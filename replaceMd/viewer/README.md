# 要件定義書 相互参照ビューア — src

`../PLAN.md` の実装。`01_要件定義書/` 配下の Markdown 182 ファイルを解析し、
機能・業務フロー・データ・システム・アクターの相互参照をブラウザで辿れるようにする。

---

## 使い方

### 1. インデックスを作る

```bash
node build-index.mjs
```

`graph-data.js` が生成される（約 1.2 MB）。オプション:

| オプション | 意味 | 既定 |
| --- | --- | --- |
| `--root <path>` | 解析対象フォルダ | `../../01_要件定義書` |
| `--out <path>` | 出力先 | `./graph-data.js` |
| `--report` | 検出した課題をすべて標準出力に出す | off |

### 2. 開く

`index.html` を**ダブルクリックするだけ**。Web サーバは不要。

`file://` では `fetch()` が CORS でブロックされるが `<script src>` は読めるため、
データは `graph-data.js` に `window.__REQ_GRAPH__` として埋め込んである（PLAN §4.2）。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `config.js` | 辞書と分類ルール。**表記が変わったらここだけ直す** |
| `parser.js` | Markdown/表の解析、ID 正規化、軽量レンダラ（Node とブラウザで共用） |
| `build-index.mjs` | 走査 → 解析 → 名前解決 → `graph-data.js` 出力 |
| `graph-data.js` | 生成物。直接編集しない |
| `index.html` / `app.js` / `style.css` | ビューア本体 |

`config.js` と `parser.js` は ESM ではなく**クラシックスクリプト**として書いてある。
ブラウザでは `window.RGConfig` / `window.RGParser`、Node では `require()` で読める。
`file://` で `type="module"` が使えないための措置。

## PLAN からの変更点

| 項目 | PLAN | 実装 | 理由 |
| --- | --- | --- | --- |
| 検索インデックス | ビルド時に bigram 転置インデックスを生成 | ロード時に正規化した本文を線形走査 | 対象は 182 ファイル・約 350KB。線形でも 1ms 未満で、生成物を 2 倍以上に膨らませる価値がなかった |
| グラフ描画 | 200 ノード未満は SVG、以上は Canvas に自動切替 | Canvas 単独（SVG は書き出し専用） | 2 系統を持つと当たり判定・ハイライトの実装が二重になる。Canvas は 769 ノード全体表示でも実用速度（レイアウト約 1.5 秒） |
| ブラウザ内での再インデックス | `<input webkitdirectory>` によるフォールバック | **未実装** | `build-index.mjs` は `fs`/`crypto` に依存しており、ブラウザで動かすには解析部の全面的な切り出しが必要。Node が使える環境では不要なため見送った |

## 解析の前提と限界（重要）

`build-index.mjs` の実行時、`--report` で確認できる課題のうち次の 3 つは
**データ側の性質によるもの**なので、内容を理解したうえで使ってほしい。

1. **AI が画像から再構成したスライドがある**
   `※このスライドは LM Studio(...) がスライドの PNG 画像から内容を再構成したものです` の注記があるスライドは、
   ビューア上で `⚠ AI が画像から再構成（要原本確認）` バッジが付く。
   ここから抽出した関係は原本と食い違う可能性があるため、参照パネルには必ず**根拠となった原文行**を併記している。

2. **媒体Web化（2.3.3）のフローグループ ⑥⑦⑨⑩⑪⑫ の名称が未確定**
   2.3.3 の「新業務フロー該当箇所」列は丸数字でフローを指すが、
   対応する 2.3.2 のスライドに丸数字見出しが残っていないものがある。
   判明したら `config.js` の `WEB_FLOW_GROUPS` に書き足せば、そのままグラフとマトリクスに反映される。

3. **見出しにフロー番号がないスライドは直前スライドの続きとして扱っている**
   2.2.2 のスライド 21 と 33 が該当。「品質チェック」タブに一覧が出る。

そのほか、正規化で吸収している既知の揺れ（PLAN §1.3）:

- 機能ID の区切り: `01_01`（2.2.3）と `01-01`（2.4.1）→ `-` に統一
- 業務フローの名称ゆれ（`取込` / `登録` など）→ **番号を主キー**にし、名称は補助照合のみ
- 全角空白・全角コロン・各種ダッシュ → 半角に正規化
- 権限一覧のセル内複数ID（`01-02<br>08-02`）→ `<br>` で分割
- 表のセル結合による空欄 → 直前の値で forward-fill
- 章番号がフロー番号として誤解決されないよう、タイトル先頭の章番号を除去してから解析

## メンテナンス

名称が変わったとき、直すのは基本的に `config.js` だけ。

| 変えたいもの | 場所 |
| --- | --- |
| システム名・別名 | `SYSTEMS` |
| アクター名・別名 | `ACTORS` |
| 丸数字 → フローグループ名 | `WEB_FLOW_GROUPS` |
| 章番号 → ドキュメント種別 | `DOC_RULES` |
| 表の列名の揺れ | `COLUMN_ALIASES` |
| ノード／エッジの色・既定表示 | `NODE_TYPES` / `EDGE_TYPES` / `DEFAULT_HIDDEN_EDGES` |

変更したら `node build-index.mjs` を再実行する。
