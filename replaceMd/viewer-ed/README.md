# ED書 業務フロー関係性ビューア

`02_ED書/` の **詳細業務フロー（110）を中心に**、画面仕様（20）・バッチ処理仕様（30）・
ファイル仕様（60）がどう繋がっているかを解析して可視化する。ゼロ依存の Vanilla JS。

```bash
node build-ed-index.mjs
```

を実行したあと `index.html` を**ダブルクリックするだけ**で動く。Web サーバは要らない。

---

## 1. 使い方

### インデックス生成

```bash
node build-ed-index.mjs
```

| オプション | 意味 | 既定 |
| --- | --- | --- |
| `--root <path>` | 解析対象 | `../02_ED書` |
| `--out <path>` | 出力先 | `.`（このフォルダ） |
| `--report` | 検出した課題をすべて標準出力に出す | off |

生成物は `ed-graph-data.js`（約 930KB）と `docs/chunk-NN.js`（本文、5 分割）。
`ed-graph-data.js` だけを起動時に読み、仕様書の本文は開いたときに `docs/` から遅延ロードする。
`file://` では `fetch()` が CORS で弾かれるが `<script src>` は読めるので、
チャンクは `script` タグ注入で取っている。

### 開く

`index.html` をダブルクリック。配布はこのフォルダごとコピーすればよい。

## 3. ビュー

### 業務フロー（メイン）
選択した業務フローを起点に、**アクター → 画面 → バッチ → ファイル → TBL** の
レイヤ図を描く。「画面・バッチ経由の間接関係も表示」を入れると、
そのフローが使う画面／バッチが触るファイル・TBL まで辿って一枚に収める。
列が 16 件を超えたら折り畳み、クリックで展開。SVG で保存できる。

下には**原文**をそのまま出し、`SE001_F03`・`SE008-B01`・`請求書管理TBL` を
クリック可能なリンクに変換している。右ペインには発リンク／被リンクを
関係種別ごとに並べ、**根拠になった原文行を必ず併記**する。

### 関係グラフ
Canvas ＋ 自前の力学レイアウト。ノード種別・関係種別のフィルタ、
起点から 1〜4 ホップのフォーカス。全体（約 700 ノード）は読めないので、
初回は選択中の業務フローを自動で起点にする。ダブルクリックで起点を移す。
PNG と関係一覧 CSV に出せる。

### マトリクス
業務フロー × 画面 / バッチ / ファイル / TBL。
セルにカーソルを合わせると根拠を出す。「未参照の列だけ表示」で抜けを抽出。CSV 出力あり。

### 仕様書
画面・バッチ・ファイル・業務フローの本文をシート単位で読む。
Excel 由来の空セルは詰めて表示している。本文中の ID もリンクになる。

### 品質チェック
カバレッジ（業務フローから何割の画面・バッチ・ファイルに辿り着けるか）と、
未解決参照・孤立要素・解析できなかったシートの一覧。

## 4. 解析の前提と限界（重要）

### 4.1 詳細業務フローの大半は AI が画像から再構成したテキスト

`110_詳細業務フロー` の各シートは Excel の**図形**で描かれているため、
元データは `LM Studio(google/gemma-4-31b-qat)` が PNG 画像から再構成した文章になっている。
該当フローには **「AI が図形シートの画像から再構成（原本要確認）」バッジ**が付く。

このため、**ここから抽出した関係は原本と食い違う可能性がある**。
関係パネル・マトリクスには常に根拠となった原文行を出しているので、
重要な判断の前には必ず原本の図を確認する。

### 4.2 業務フロー本文には ID がほとんど書かれていない

40 シート中、明示的な画面ID は 2 件、バッチID は 12 件しか現れない。
残りは「PDF作成送信（請求）」のような**日本語の名前**で書かれている。
そのため画面名・バッチ名・ファイル名の辞書と照合して補完している（＝推定リンク）。

誤爆を避けるため、照合キーは **6 文字以上**に限っている
（`NAME_MATCH_MIN`。これを下げると「請求番号」のような一般語で誤リンクが増える）。

### 4.3 一覧にあるが詳細シートが無い業務フローが 31 件ある

`TPC詳細業務フロー一覧.md` に載っている 69 フローのうち、
詳細シートがあるのは 38 件。残りは一覧の行だけが存在する。

これらは**一覧の業務フロー名と機能グループ名の一致**だけで機能グループに寄せている
（例: `GF_404 回線按分情報設定` → 画面機能 `MK001 回線按分情報設定`）。
根拠が名前しか無いので、すべて推定として扱う。ツリーでは「詳細なし」と表示する。

### 4.4 Excel のふりがなが本文末尾に連結されている

`掲示板ケイジバン` `TOP画面（顧客）ガメンコキャク` のように、
Excel の phonetic guide がセル本文の末尾に繋がっている。

表示時に除去しているが、「モバイル回線別レポート」のように
**語そのものがカタカナで終わる正当な名前**を壊さないよう、次の 2 段構えで判定している。

1. 末尾のカタカナ列が `KATAKANA_TAIL_KEEP`（レポート・データ・フロー等 60 語）に一致したら残す
2. ふりがなは漢字の読みなので、カタカナ列が**残りの漢字数以上の長さ**のときだけ除去する

ヘッダの「ふりがな表示」で原文に戻せる。判定を直すのは `ed-parser.js` の
`KATAKANA_TAIL_KEEP` と `stripRuby()` の 2 か所だけ。

### 4.5 バッチ仕様書にはテンプレートが 3 世代混在している

`30_バッチ処理仕様` の `概要` シートは、同じ内容を違う書式で書いている。

| 表紙の帳票名 | 冊数 | 節見出しの書き方 |
| --- | --- | --- |
| 機能仕様書 | 49 | `◆入力一覧`（◆ が同じセル） / `処理概要` |
| バッチ処理仕様書 | 15 | `◆` ＋ `入力一覧`（◆ が別セル） / `< 処理概要 >` |
| （Markdown 見出し） | 1 | `## 入力一覧` / `# 処理概要` |

表の中身（`入力 | 区分 | 備考`）は 3 世代とも同じなので、`SEC` の正規表現で見出しだけ吸収している。
**新しい書式が増えたらここを直す。** 見落とすと入出力の関係がごっそり抜ける
（実際、当初は `< 処理概要 >` 形式しか見ておらず 90 冊中 19 冊しか読めていなかった）。

### 4.6 その他

- `.xlsx` は**フォルダ名**（1 冊の仕様書 = 1 フォルダ、シート = その中の .md）。実ファイルは全て .md。
- ID を持たない一覧・共通仕様のフォルダ（`ED_T_マスタロックフラグ制御` 等 9 件）は関係グラフに載せていない。品質チェックの「対象外にしたフォルダ」に出る。
- TBL ノードは各仕様書からの抽出で作った**派生ノード**で、`50_データベース仕様` とは突き合わせていない。表記ゆれ（`請求/収納進捗TBL` と `請求収納進捗TBL` 等）はそのまま別ノードになりうる。

## 5. ファイル構成

| ファイル | 役割 |
| --- | --- |
| `build-ed-index.mjs` | 走査 → 解析 → 名前解決 → `ed-graph-data.js` と `docs/` を出力 |
| `ed-parser.js` | Excel ダンプ表のセル解析、ふりがな除去、照合キー生成。Node とブラウザで共用 |
| `test-parser.mjs` | `ed-parser.js` の回帰テスト（`node test-parser.mjs`） |
| `ed-graph-data.js` | 生成物。直接編集しない |
| `docs/chunk-NN.js` | 生成物（仕様書の本文） |
| `index.html` / `app.js` / `style.css` | ビューア本体 |

`ed-parser.js` は ESM ではなく**クラシックスクリプト**。
ブラウザでは `window.EDParser`、Node では `require()` で読む
（`file://` で `type="module"` が使えないため）。

## 6. 直すとき

| 変えたいもの | 場所 |
| --- | --- |
| ふりがな判定（削りすぎ／残りすぎ） | `ed-parser.js` の `KATAKANA_TAIL_KEEP` / `RUBY_WINDOW`。触ったら `node test-parser.mjs` |
| 名称一致の厳しさ | `build-ed-index.mjs` の `NAME_MATCH_MIN`（既定 6） |
| アクターの辞書 | `build-ed-index.mjs` の `ACTORS` |
| ヘッダ語の誤検出除け | `build-ed-index.mjs` の `BAD_VALUE` |
| ノード／関係の色・ラベル | `app.js` の `KIND` / `ETYPE` |
| 関係マップの 1 列あたり表示件数 | `app.js` の `MAP_CAP`（既定 16） |

変更したら `node build-ed-index.mjs` を再実行する。
